# 디스패치 페이지 (휴대폰용)

휴대폰에서 **메일로 일을 맡기는** 메신저형 화면입니다. 서버가 없는 정적 페이지 하나(`index.html` + 아이콘 + `manifest.webmanifest`)라
어디에 올려도 됩니다. 페이지 안에는 아무 주소도 들어 있지 않고, 메일 주소·작업 폴더 키·이슈 키 앞부분·Google 클라이언트 ID 는
**그 휴대폰 브라우저에만** 저장됩니다.

두 가지 방식으로 씁니다.

| 방식 | 보내기 | 답 보기 | 준비 |
|---|---|---|---|
| **메일 앱** (기본) | `mailto:` 로 메일 앱이 제목·본문이 채워진 채 열리고, 보내기를 한 번 더 누른다 | 메일 앱으로 온다 | 없음 |
| **Gmail** | 페이지가 Gmail API 로 바로 보낸다(사진 첨부 가능) | 대화 번호(`[T12]`)마다 방이 생기고 PC 의 답이 말풍선으로 온다. 선택지 단추·멈춤 단추·접수 표시 | Google 클라이언트 ID |

PC 의 메일 게이트웨이(`mail-gateway.py`)가 받아 실행하고 결과를 메일로 회신합니다.

## 올리는 법 (아무 정적 호스팅이나)

- **GitHub Pages** — 이 폴더만 담은 저장소를 만들고(또는 저장소의 `/docs` 등으로 복사), Settings → Pages 에서 브랜치를 고르면
  `https://<계정>.github.io/<저장소>/` 로 열립니다. 페이지에 비밀값이 없으니 공개 저장소여도 됩니다.
- **사내 웹 서버 · Netlify · Cloudflare Pages · S3 등** — 이 폴더의 파일을 그대로 올리면 됩니다. HTTPS 면 홈 화면에 앱처럼 추가할 수 있습니다.
- 파일로 바로 열어도(`file://`) 메일 앱 방식은 되지만, 휴대폰에선 설정 저장·홈 화면 추가가 안 될 수 있고 Gmail 방식은 안 됩니다.

## 처음 쓸 때

1. 휴대폰으로 페이지를 열고 **설정** — 지시를 받을 내 메일 주소(PC 게이트웨이가 보는 주소, `config.local.json` 의 `mail.user`)를 넣습니다.
2. 작업 폴더 키(`dispatch.workdir_keys` 의 키, 예: `docs`)와 이슈 키 앞부분(`dispatch.issue_prefix`, 예: `PROJ-`)·이슈 처리 명령
   (`dispatch.issue_command`)은 PC 설정과 같게 넣습니다. 이슈 키 앞부분을 비우면 **이슈** 탭이 숨겨집니다.
3. 브라우저 메뉴의 **홈 화면에 추가**로 앱처럼 씁니다.

보낸 메일의 발신 주소가 PC 설정의 `dispatch.allowed_senders` 에 있어야 실행됩니다(비어 있으면 모든 메일을 무시합니다).
태그(`#c` 읽기 · `#cw` 수정 허용)를 PC 에서 바꿨다면 `index.html` 의 `TAG` 도 같게 고칩니다.

### 회사 주소가 아닌 메일로 보낼 때 — 암호 단어

휴대폰 기본 메일이 개인 주소(Gmail·iCloud 등)면 `allowed_senders` 에 넣는 대신 PC 의 암호 단어 목록에 그 주소와 단어를 넣고,
페이지 설정 **암호 단어**에 같은 단어를 넣습니다. 보낼 때 자동으로 붙습니다(메일 앱은 제목 끝 `[k:단어]`, Gmail 은 본문 마지막 줄).
단어가 없거나 틀린 메일은 PC 가 무시합니다. 단어는 휴대폰과 PC 설정 파일에만 두고 페이지 소스에 넣지 마세요.

## Gmail 방식 켜기

1. [Google Cloud 콘솔](https://console.cloud.google.com/)에서 프로젝트를 하나 만들고 **Gmail API** 를 사용 설정합니다(결제 계정은 필요 없습니다).
2. OAuth 동의 화면 — 외부 · 테스트 사용자에 내 Gmail 주소를 넣습니다. 범위는 `gmail.readonly` · `gmail.send` 두 개입니다.
3. 사용자 인증 정보 → **OAuth 클라이언트 ID** → 유형 **웹 애플리케이션**. 승인된 JavaScript 원본에 페이지 주소의 원본
   (예: `https://<계정>.github.io`), 승인된 리디렉션 URI 에 **페이지 주소 그대로**(예: `https://<계정>.github.io/<저장소>/`)를 넣습니다.
4. 만들어진 클라이언트 ID(`….apps.googleusercontent.com`)를 페이지 설정 **Google 클라이언트 ID** 에 넣고 저장하면 Google 로그인 화면이 열립니다.
   토큰은 1시간짜리로 이 기기에만 남고, 끊기면 화면 없이 조용히 다시 받아 옵니다.
5. PC 가 그 Gmail 주소에서 온 지시를 받도록 암호 단어(위)를 설정합니다. PC 는 회신을 그 Gmail 로도 보냅니다.

페이지는 PC 메일 주소와 오간 메일(스팸함 포함)을 몇 초마다 읽어 말풍선을 만듭니다. 대화방을 지우거나 기록을 비우는 것은
**이 기기 화면에서만**입니다(Gmail·PC 의 메일은 그대로 — 페이지에는 삭제 권한이 없습니다).

### 회사 메일이 Gmail 에서 온 새 지시를 붙잡을 때

회사 메일의 스팸 장비가 외부 Gmail(API) 로 보낸 **새** 메일을 몇 분씩 격리하는 곳이 있습니다(답장은 대개 통과).
그럴 때 고르는 길이 둘입니다.

- **나에게 보내기(권장)** — PC 에서 `python mail-gateway.py --setup-gmail` 창에 Gmail 주소와 앱 비밀번호를 넣어
  Gmail 직접 읽기(`config.local.json` 의 `dispatch.gmail`)를 켜고 — 그 주소는 `dispatch.keyed_senders` 에도 있어야 합니다 — 페이지 설정
  **PC 가 내 Gmail 을 직접 읽어요**를 켭니다. 지시·답·멈춤이 전부 내 Gmail 로 가고 PC 가 Gmail 받은편지함에서 바로 읽으니
  회사 메일을 거치지 않습니다. 앱 비밀번호는 Google 계정 → 보안 → 2단계 인증을 켠 뒤 '앱 비밀번호'에서 만듭니다.
- **새 지시는 메일 앱으로** — PC 쪽 설정 없이, 새 지시만 메일 앱으로 보냅니다(보내기를 한 번 더 누름). 이어 말하기·답하기는 Gmail 그대로.
