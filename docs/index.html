업무 자동화 키트 — 도움말

어느 회사에서나 쓰는 Windows 업무 자동화 키트. 트레이에 상주하는 매크로 허브가 예약 작업·감시·알림을 맡고, 회사마다 다른 값은 config.local.json 한 곳에 둔다.

시작하기기능기능별 설정알림 받는 쪽매크로 만들기허브 API문제 해결

시작하기

  1. 설치 파일(WorkKitSetup-…exe)을 실행하거나, 저장소를 받아 python setup.py — 처음 설정(회사 이름·메일 계정·알림 받는 곳).
  2. 허브를 띄운다(트레이 아이콘). 화면은 이 PC 에서만 열린다: http://127.0.0.1:8630/
  3. 운영 화면 /ops 의 「⏰ 예약 작업」에서 쓸 기능을 켜고, 대상은 config.local.json 에 적는다(아래 견본).
  4. 슬랙·Teams 로도 받으려면 python setup.py --webhook. 알림 시험은 python setup.py --test.
비밀번호·토큰·웹훅 주소는 Windows DPAPI 로 이 PC·이 사용자에 묶어 암호화한 값만 파일에 남는다. 허브는 127.0.0.1 에만 열린다 — 다른 PC 에서 들어올 수 없다.

자세한 동작 (tools/macro-hub/macros/job_tidy.py)
폴더 정리 — 오래된 파일을 보관 폴더(archive_to\YYYY-MM\)로 옮긴다. 절대 지우지 않는다.

- 드라이브 맨 위·C:\Windows·Program Files·사용자 폴더 맨 위는 실수 한 번이 크게 번지므로 거절한다.
- 매개변수 {"dry_run": true} 면 옮길 목록만 보여 준다(예약과 상관없이 모든 켜진 항목). 손으로 '지금 실행'하면
  예약 시각을 기다리지 않고 모든 켜진 항목을 정리한다.
설정 견본
{
  "tidy": [
    {
      "name": "다운로드 정리",
      "folder": "%USERPROFILE%\\Downloads",
      "older_than_days": 30,
      "archive_to": "%USERPROFILE%\\Downloads\\_보관",

}

사이트·서버 감시 monitors

자세한 동작 (tools/macro-hub/macros/job_monitors.py)
사이트·서버 살아 있나 감시 — config 의 "monitors" 갈래.

    "monitors": {"every_min": 5, "fail_after": 2, "cert_warn_days": 14,
                 "targets": [{"name": "홈페이지", "url": "https://..."}, {"name": "DB", "host": "10.0.0.10", "port": 5432}]}

허브는 1분마다 깨우고, 실제 확인은 every_min 분마다 한다(손으로 '실행' 하면 바로).
- URL: HEAD 로 묻고 안 되면 GET 으로 다시(HEAD 를 거절하는 서버가 많다). 응답 코드 400 미만이면 정상, 리다이렉트는 따라간다.
- host+port: TCP 연결만 해 본다.
- 한 번 실패로는 알리지 않는다 — fail_after 번 내리 실패해야 '접속 안 됨'(잠깐 끊긴 걸로 메일 폭탄이 되지 않게).
  내려가면 한 번, 돌아오면 한 번만 메일을 보낸다(얼마나 끊겼는지 함께).
- https 는 서버 인증서 만료일도 읽어 cert_warn_days 일 안으로 들어오면 알린다(하루 한 번까지, D-3 안쪽에서 한 번 더).
대상이 죽어 있는 것은 이 매크로의 실패가 아니다 — 예외를 던지지 않는다(허브 실패 알림과 겹치지 않게).
설정이 잘못된 대상만 상태를 남긴 뒤 마지막에 예외로 알린다.
설정 견본
{
  "monitors": {
    "every_min": 5,
    "fail_after": 2,
    "cert_warn_days": 14,
    "targets": [
      {
        "name": "회사 홈페이지",
        "url": "https://www.example.com/"
      },
      {
        "name": "사내 DB",
        "host": "10.0.0.10",
        "port": 5432
      }
    ]
  }
}

폴더 백업 backups

자세한 동작 (tools/macro-hub/macros/job_backup.py)
폴더 백업 — config 의 "backups" 갈래(목록).

    "backups": [{"name": "문서 백업", "source": "%USERPROFILE%\Documents", "dest": "D:\Backup\Documents",
                 "at": "12:30", "days": "mon-fri", "keep": 7, "exclude": ["*.tmp", "~$*"], "enabled": true}]

허브가 1분마다 깨우면 at/days 가 된 항목만 돈다(손으로 '실행' 하면 켜진 항목 모두 — only 로 하나만 고를 수 있다).
돌 때마다 dest\YYYY-MM-DD_HHMM 날짜 폴더를 새로 만들어 robocopy 로 통째로 복사한다(날짜별 스냅숏).
성공하면 keep 개보다 오래된 스냅숏을 지운다 — **dest 바로 아래, 이름이 정확히 날짜 모양인 폴더만** 지운다.
다른 것은 절대 건드리지 않는다. dest 가 source 안에 있으면(복사가 끝없이 자기 자신을 품는다) 거절한다.
실패한 스냅숏은 '_실패' 를 붙여 남겨 둔다 — 날짜 모양이 아니게 되므로 정리 대상이 아니고, 무엇이 빠졌는지 볼 수 있다.
하나라도 실패하면 상태를 남긴 뒤 마지막에 예외를 던진다(허브가 실패 알림 메일을 보낸다).
params {"dry_run": true} 면 robocopy /L(목록만) 로 돌리고 지우지도, 실행 기록을 남기지도 않는다.
설정 견본
{
  "backups": [
    {
      "name": "문서 백업",
      "source": "%USERPROFILE%\\Documents",
      "dest": "D:\\Backup\\Documents",
      "at": "12:30",
      "days": "mon-fri",
      "keep": 7,
      "exclude": [
        "*.tmp",
        "~$*"
      ],
      "enabled": false
    }
  ]
}

마켓 장애 공지 감시 market_notice

'우리 문제냐 마켓 문제냐' — 마켓·결제·택배의 공개 장애·점검 공지(로그인 없이 보이는 것만)를 every_min 분마다(15분 이상) 모아, 제목에 keywords 가 든 공지가 새로 뜨면 알린다. 처음 읽을 때 이미 있던 공지는 알리지 않는다. failures 의 로그에서 match 줄을 실패로 세어, 지난 1시간이 spike_min 건 이상이고 평소(그 전 24시간 시간당 평균)의 spike_ratio 배 이상이면 같은 시간대(앞뒤 window_min 분) 공지를 붙여 알린다.

견본 다섯 곳은 2026-10 에 로그인 없이 읽히고 robots.txt 가 허용하는 것을 확인했다(쓰지 않을 것은 지운다). robots.txt 가 막는 곳은 읽지 않는다 — 11번가·한진·CJ대한통운 등. 쿠팡 Wing·롯데ON·스마트스토어센터 공지는 로그인 뒤라 넣을 수 없다. type: rss(RSS·Atom 주소) · statuspage(statuspage.io 상태 페이지 주소 — 뒤에 /history.rss 를 붙여 읽고 전부 장애로 봄) · html(정적 목록 페이지 — item 정규식에 (?P<title>…) 필수, (?P<link>…)·(?P<date>…)·(?P<tag>…) 선택) · json(items·title·date·link·tag·emergency 키 경로). 출처마다 keywords 를 따로 줄 수 있다.

path 는 와일드카드 가능(최근 26시간 안에 바뀐 파일만, 파일마다 끝 2MB). 줄의 시각은 기본으로 '2026-10-14 09:30[:00]' · '2026.10.14 09:30' 꼴을 찾는다 — 다르면 time 에 (시각) 묶음 하나짜리 정규식.

자세한 동작 (tools/macro-hub/macros/job_market_notice.py)
'우리 문제냐 마켓 문제냐' — 마켓·결제·택배의 공개 장애·점검 공지를 모으고, 내 실패 기록과 시간을 맞춰 본다.
config 의 "market_notice" 갈래.

    "market_notice": {
      "every_min": 30, "keywords": ["장애", "점검", "지연", "오류", "중단"], "window_min": 120,

API 호출 한도 조절 · 미터기 rate_limits

마켓 API 호출 한도 — 직접 만든 연동 도구가 tools/macro-hub/ratelimit.py 의 Limiter 로 호출하면, 같은 이름은 여러 프로그램이 한 한도를 나눠 쓰고(파일 잠금), 응답 머리글(Retry-After·X-RateLimit-*)과 429 를 보고 쉬었다가 다시 보낸다. 이름마다 limit 회 / window_sec 초. 미터기(job_rate_meter)가 5분마다 운영 화면 「📊 기능 상태」에 사용량을 보이고, _warn_pct % 를 넘거나 429 로 막히면 알린다. 한도 숫자는 각 마켓 개발자 문서에서 확인해 적는다.

자세한 동작 (tools/macro-hub/ratelimit.py)
마켓 API 호출 한도 지키기 — 여러 프로그램이 같은 한도를 나눠 쓰는 조절 큐 + 미터기. 표준 라이브러리만.

    import ratelimit
    lim = ratelimit.Limiter('cafe24', limit=3000, window_sec=600)       # 10분 3,000회
    with ratelimit.guarded_urlopen(lim, req) as r:                       # 차례를 기다렸다가 보내고, 429 면 쉬었다 다시
        data = r.read()
    lim.acquire()   # 직접 부를 때 — 자리가 날 때까지 기다린다(돌려주는 값: 기다린 초)
    lim.observe(resp.headers, resp.status)                               # 응답 머리글로 남은 횟수·쉬는 시간 배우기

한도는 config "rate_limits" 갈래에 둘 수 있다 — {"cafe24": {"limit": 3000, "window_sec": 600}} → ratelimit.from_config('cafe24').
- 같은 이름의 Limiter 는 data.local/rate_limits/<이름>.json 을 같이 쓴다(파일 잠금) — 매크로·도구·게이트웨이가 따로 돌아도
  한도를 함께 센다. 창은 미끄러지는 창(window_sec 안의 호출 시각 목록).
- 응답 머리글: Retry-After(초·날짜), X-RateLimit-Remaining/-Limit/-Reset 류(대소문자·접두어 상관없이 'remaining'·'reset' 을
  찾는다), 429·503 이면 Retry-After(없으면 지수 대기)만큼 이 이름 전체가 쉰다.
- 미터기: usage() → 창 안 사용량·한도·비율·쉬는 중인지·최근 429. 매크로 job_rate_meter 가 운영 화면 「📊 기능 상태」와 알림에 쓴다.

디스패치(메일 → Claude Code, 고급) dispatch

메일로 AI(Claude Code)에게 일 맡기기 — 이 PC 에 Claude Code 가 깔려 있어야 한다. 기본 꺼짐. 제목이 태그로 시작하는 메일을 mail-gateway.py 가 받아 inbox-worker.ps1 이 claude -p 로 실행하고 결과를 회신한다.

자기에게 보낸 메일을 메일 규칙이 딴 폴더로 옮기는 서버면 그 폴더도 넣는다 — 예: ["INBOX", "Inbox.내게쓴메일"] (폴더 이름은 서버마다 다르다)

지시를 받아 줄 보낸 사람 주소. 비어 있으면 모든 메일을 무시한다(보통 내 주소 하나).

제목의 '@키' 로 고르는 작업 폴더 — 예: {"docs": "D:\\work\\docs"} 이면 '#c @docs 요약해줘'

smtp = 회신을 실제로 발송 · append = 받은편지함(INBOX)에 직접 넣기(자기에게 보낸 메일이 딴 폴더로 가거나 SMTP 발송이 막힌 서버). 디스패치 대화 앱도 지시를 같은 방법으로 넣는다(chat_send_mode 로 따로 정할 수 있다).

read_tools = 읽기 태그(#c) 지시에 줄 도구 · write_tools = 쓰기 태그(#cw) 지시에 줄 도구 · extra_tools = 잡이 요청할 수 있는 도구 상한에 더할 이름(기본 상한은 Read·Glob·Grep·Edit·Write·NotebookEdit·Bash — MCP 도구를 쓰려면 여기에 이름을 넣는다).

쓰기 태그로 온 새 지시는 실행 전에 확인 메일을 보내고 '1'(확인) 답장을 기다린다. confirm_ttl_min 분 안에 답이 없으면 취소.

Claude 가 선택지로 물은 뒤 이 시간(시간 단위)이 지나도록 답이 없으면 질문을 닫고 그 대화에 알림 1통 — 대화 앱·폰의 '답할 것' 에서 빠진다. 늦게 답해도 대화는 그대로 이어진다(번호 답도). 처음 켤 때·일주일 넘은 질문은 알림 없이 닫는다. 0 이면 끈다.

true 면 서버가 붙인 Authentication-Results 에 dkim=pass 또는 spf=pass 가 있는 메일만 받는다(From 위조 방지). 켜기 전에 게이트웨이 로그의 '[인증]' 줄로 서버가 그 헤더를 붙이는지 확인할 것.

폰(개인 메일) 지시 받기 — allowed_senders 밖의 개인 주소(iCloud·Gmail 등)라도 그 주소의 암호 단어 '[k:단어]' 가 제목 끝이나 본문 한 줄로 붙어 있으면 받는다(폰 페이지가 설정의 암호 단어를 자동으로 붙인다). 예: {"me@example.com": "아무도모를단어"}. 이 주소에서 온 지시는 회신·접수 신호(읽음 '1')를 그 주소로도 보내고, 사진 첨부(최대 5장)는 inbox\attachments 에 저장해 Claude 가 읽게 한다. 폰 대화방의 '멈춤' 은 돌고 있는 일을 끊는다.

회사 모드 — 이 폴더(와 그 아래)에서 돈 일의 결과·질문은 회사 메일함에만 둔다. 폰(keyed_senders·Gmail 개인 주소)으로는 내용 없는 알림(끝남 · 질문 N개 — 회사 메일함에서 보기)만 가고, 거기에 번호로 답장하면 그대로 이어진다. null 이면 default_workdir 하나(기본으로 켜짐), [] 면 끈다. %USERPROFILE% 같은 환경 변수를 써도 된다.

폴더별 정책 — 키는 workdir_keys 이름(또는 "default"), 실제 경로로 맞춘다. from = 지시를 받아 줄 출처("company" = allowed_senders 회사 주소, "phone" = 암호 단어 개인 주소·Gmail, 없으면 둘 다) · write_from = 수정 지시(#cw)를 받아 줄 출처(없으면 from 과 같음, [] 면 수정 지시 안 받음). 걸리면 실행하지 않고 이유를 회신한다. 예: {"default": {"write_from": ["company"]}}

암호 단어 주소의 회신·접수 신호를 다른 주소로 받을 때 — 예: {"me@icloud.example": "me@gmail.example"} (새 지시는 폰 메일 앱으로, 답은 폰 페이지(Gmail)로).

스팸함도 볼 때 그 폴더 이름(서버마다 다르다 — 예: ["Spam"]). 회사 메일이 폰에서 온 지시를 스팸으로 돌릴 때 쓴다. 여기서는 암호 단어가 맞는 메일만 받는다(회사 주소라도 믿지 않는다).

Gmail 직접 읽기 — 회사 스팸 장비가 외부 Gmail(API) 로 보낸 새 지시를 몇 분씩 붙잡는 경우, 폰 페이지가 지시를 '나에게' 보내고 PC 가 Gmail 받은편지함을 바로 읽는다(그 주소 자신이 보낸 메일 + 암호 단어만). 받은 지시는 대화 앱이 보도록 회사 INBOX 에 사본을 넣는다. 손으로 채우지 말고 'python mail-gateway.py --setup-gmail' 로 — Google 계정의 2단계 인증을 켜고 만든 '앱 비밀번호'를 넣으면 {"user", "password_enc"} 가 들어간다. 그 Gmail 주소는 keyed_senders 에도 있어야 한다.

이슈 처리 칸 — issue_prefix(예: "PROJ-")를 넣어야 켜진다. '#cw <issue_command> PROJ-123' 메일은 issue_tools · issue_disallowed_tools 로 돈다(비면 write_tools). issue_command 는 그 이슈를 처리할 Claude Code 스킬(슬래시 명령) 이름. issue_tools 에 MCP 도구를 넣었다면 extra_tools 에도 넣는다.

poll_sec = 메일함 확인 간격 · lookback_days = 이 기간 안의 메일만 본다 · max_per_cycle = 한 번에 접수할 최대 건수 · max_prompt_chars = 지시 길이 상한 · timeout_sec = 작업 하나의 제한 시간 · keep_jobs = 남겨 둘 끝난 작업 수

자세한 동작 (mail-gateway.py)
메일 게이트웨이 — 휴대폰(또는 어느 PC)에서 보낸 지시 메일을 작업 인박스 큐에 넣고, 결과를 회신한다.

폰↔PC 직접 연결은 사내 방화벽·망분리로 막혀 있는 일이 많다. 그래서 양쪽 모두 닿는
회사 메일(IMAP/SMTP)을 통로로 쓴다. 내용이 회사 메일 밖으로 나가지 않는다는 것이 이 방식을 고른 이유다.

흐름:
    감시 폴더의 [제목이 태그로 시작하는] 메일 발견
      → 발신자가 허용 목록(dispatch.allowed_senders)인지 확인 — 목록이 비면 전부 무시
      → inbox/jobs/<id>.json 생성 (source=mail)   ← inbox-worker.ps1 이 집어 claude -p 로 실행한다
      → 메일을 읽음(\Seen) 처리
    워커가 done/error 로 바꾼 메일발 작업 발견
      → 원본에 회신(In-Reply-To 로 스레드 유지, 답장에도 Message-ID 를 남긴다)
      → replied=true 로 표시

들어온 메일이 예전 답장에 대한 재답장(In-Reply-To/References 로 알 수 있다)이면
그 잡의 session_id 를 찾아 새 잡에 resume_id 로 실어 보낸다 — inbox-worker.ps1 이
이 값을 보면 새 세션 대신 claude -p --resume <id> 로 이어서 돌린다. 폰 메일 앱이
답장 제목에 붙이는 'Re:' 는 자동으로 벗겨 태그 매칭을 그대로 통과시킨다.

설정은 저장소 맨 위 config.local.json 한 곳이다(견본 config.example.json, 처음 설정은 python setup.py).

  dispatch  이 기능의 동작(enabled · tags · write_tags · folders · allowed_senders · default_workdir ·
            workdir_keys · reply_mode · issue_prefix …). enabled 가 false 면 아무것도 하지 않는다.
접속·복호화는 tools\macro-hub\kit.py 의 공통 코드를 쓴다.

실행(claude 호출)은 inbox-worker.ps1 이 담당한다. 여기서는 큐에 넣고 회신만 한다.

AI 공유 위키 — 내 작업 흔적(이슈 출처 + git 커밋 + 선택 기능)을 모아 주간 업무 보고 초안과 업무 공유 발표 준비 자료를 만든다.

  weekly    : 이번 주(월요일~오늘)를 모아 주간 보고 초안을 쓰게 하고(claude CLI 또는 ollama)
              <wiki_dir>\reports\YYYYMMDD_주간보고.md 로 저장한 뒤 메일로 보낸다(--no-mail 이면 파일만).
              LLM 이 실패해도 모은 원자료(이슈·커밋 목록)를 대신 보낸다. 허브의 job_weekly_report 가 정한 요일·시각에 부른다.
  collect   : 기간 안의 이슈·커밋·(선택) MR·하네스 기록을 이슈 키로 묶어 wiki\tickets\<part>\<키>.md + INDEX.md 로 쌓는다(LLM 없음).
  present   : wiki 로 업무 공유 발표 준비 자료를 만든다(claude -p — 사용량 큼, --engine ollama 는 맛보기).
  run       : collect 후 present.
  serve     : 이 PC 에서만 열리는 웹 화면(127.0.0.1) — 위키 보기·발표 선택·수집·주간 보고 초안.
  set-token : 이슈 출처 토큰을 DPAPI 로 암호화해 config.local.json 에 넣는다(--gitlab = MR 리뷰용, --other = 다른 파트 clone 용).

알림 받는 쪽 (웹훅)

모든 알림(실패 알림·감시·로그인·키·마켓 공지·카테고리)은 메일과 함께 notify.channels 의 출구로도 간다. 출구 종류: slack, teams, discord, google_chat, webhook. 주소는 python setup.py --webhook 으로 넣고, https 만 받는다.

일반 웹훅 type: webhook 이 보내는 JSON

{
  "subject": "[감시] 홈페이지 접속 안 됨",
  "body": "홈페이지(https://example.com)에 접속할 수 없습니다.",
  "ts": 1791900000,
  "source": "예시상사"
}

서명 비밀을 넣었으면 머리글 X-Kit-Signature: sha256=<HMAC-SHA256(비밀, 본문)> 이 붙는다. 받는 쪽에서 본문 바이트 그대로 확인한다.

Python
import hashlib, hmac

def verify(secret: str, body: bytes, header: str) -> bool:
    """X-Kit-Signature: sha256=<hex> 를 확인한다. body 는 받은 그대로의 바이트."""
    want = "sha256=" + hmac.new(secret.encode("utf-8"), body, hashlib.sha256).hexdigest()
    return hmac.compare_digest(want, header or "")
Node.js
const crypto = require("crypto");

function verify(secret, rawBody, header) {          // rawBody: 받은 그대로의 Buffer
  const want = "sha256=" + crypto.createHmac("sha256", secret).update(rawBody).digest("hex");
  return header && want.length === header.length && crypto.timingSafeEqual(Buffer.from(want), Buffer.from(header));
}

보낸 기록(성공·실패·HTTP 코드)은 운영 화면 「📊 기능 상태」 → 알림 출구 · 보낸 기록. 주소는 기록에 남지 않는다.

매크로 만들기

tools/macro-hub/macros.local/ 에 파이썬 파일 하나를 두면 허브 목록에 뜬다(이 폴더는 git 에 들어가지 않는다). META 로 이름·트리거를, run(ctx) 로 할 일을 적는다. 결과를 운영 화면에 남기려면 kit.write_status(이름, items).

# macros.local/job_my_report.py — 허브가 이 폴더를 읽어 목록에 띄운다(처음엔 꺼져 있음)
import kit

META = {
    "name": "내 보고서 확인 (평일 09:10)",
    "desc": "보고서 폴더에 오늘 파일이 있는지 보고 없으면 알린다.",
    "kind": "ctx",
    "target": "desktop",
    "triggers": [{"type": "schedule", "at": "09:10", "days": "mon-fri"}],
    "timeout": 120,
}


def run(ctx):
    import datetime, os
    folder = kit.expand(r"%USERPROFILE%\Documents\reports")
    today = datetime.date.today().strftime("%Y%m%d")
    if not any(today in n for n in os.listdir(folder)):
        kit.alert("[보고서] 오늘 파일 없음", "%s 에 %s 파일이 없습니다." % (folder, today))   # 메일 + 알림 출구
        ctx.notify("보고서", "오늘 파일이 없습니다", "warning")                        # 트레이 풍선
    ctx.log("확인 끝")

문제 해결

  • 알림 메일이 안 온다 — python setup.py --test. 스팸함도 본다. 회사 메일이 자기에게 보낸 메일을 딴 폴더로 치우면 mail.alert_via 를 append 로.
  • 사내망에서 https 오류 — 회사 TLS 검사 장비의 루트 인증서(.pem)를 mail.ca_bundle 에.
  • 기능이 안 돈다 — 운영 화면 「⏰ 예약 작업」에서 켜져 있는지, 「📊 기능 상태」의 마지막 결과·오류를 본다. 허브가 꺼져 있던 동안 놓친 실행은 따라잡지 않는다.
  • 누가 무엇을 바꿨나 — 운영 화면 「📜 변경 이력」(켜고 끄기·예약 시각·설정 변경 — 값은 남기지 않음).
  • 마켓 공지가 안 읽힌다 — 그 사이트 robots.txt 가 자동 수집을 막으면 읽지 않는다(끄는 설정 없음). 로그인 뒤에 있는 공지는 넣을 수 없다.
